# seed/ — моковые данные демо-стенда

Три скрипта наполняют чистую установку данными для демонстрации. Их запускает `scripts/seed_demo.sh`
(его же вызывает `install.sh`, если выбрано «залить моковые данные»).

| Этап (`SEED_ONLY`) | Файл | Что создаёт |
|---|---|---|
| `catalogs` | `catalogs.mjs` | направления, причины отказа, **праздники 2026**, пользовательские поля сделки |
| `demo` | `seed-demo.mjs` | команда «Отдел вузов», продукты, реестр ЕГРЮЛ (27 записей), SLA-правила, 14 организаций, контакты, ~39 сделок B2B/B2C по статусам воронки, комментарии, задачи, участники |
| `erasure` | `erasure.mjs` | запросы на удаление ПДн в разных состояниях и согласования «четыре глаза» (два администратора) |

Как это работает: одноразовый контейнер `seed-demo` (`node:24-alpine`, образ лежит в офлайн-бандле) ходит в API
через Caddy внутри сети compose (`http://caddy:8080`) под демо-учётками и Bearer-токеном. Снаружи ни DNS, ни TLS,
ни интернет не нужны. Скрипты идемпотентны: организации ищутся по ИНН, контакты по фамилии, сделки по названию,
справочники по коду — повторный запуск ничего не дублирует. Побочный эффект: у демо-учёток принимается согласие
на обработку ПДн.

Только для профиля `demo`: в `prod` вход по Bearer ограничен ролью `INTEGRATION`, а `/config.json` не отдаёт
секрет клиента — сиды там не работают и запускать их нельзя (`seed_demo.sh` откажется).

## Не править руками

Файлы здесь — копии из репозитория **frontend** (`tools/seed-demo.mjs`, `tools/scenarios/b-seed-catalogs.mjs`,
`tools/scenarios/lead-seed-erasure.mjs`); меняется только строка импорта. `lib.mjs` — урезанная выжимка
`frontend/tools/lib.mjs` без playwright. Обновление:

```bash
bash scripts/sync_seed.sh --frontend-dir ../frontend          # перезаписать seed/ из frontend
bash scripts/sync_seed.sh --frontend-dir ../frontend --check  # только сверить (код 1 при расхождении)
```
